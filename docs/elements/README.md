# Detail for project parts

Add records here when a part of the project needs more detail than fits clearly
in the [overall approach](../design.md). A part might be a workstream, activity,
section of a publication, event session, service or component.

Describe its purpose, responsibilities, interactions and dependencies. Link it
to the expectations it serves and to relevant mocks, checks, working materials
and evidence. Use consistent names across those references.

Keep its relationship to the whole project visible. Create separate files or
subfolders when the detail helps people carry out or understand the work;
several parts can share one record.
